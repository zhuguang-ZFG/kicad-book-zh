# 第 13 章：仿真与电路验证——ngspice、模型与结果证据

> **开门一句话：**仿真不是“跑出一条曲线”，而是先写下一个能被判定的问题，再用模型和分析去回答它；模型错了，曲线越漂亮越危险。

## 学习目标

读完这章，你能做到：

- 把“仿真一下”改写成“问题、判据、模型、分析”四件套；
- 在 KiCad 10 原理图里给器件分配或推断 SPICE 模型，并检查引脚映射；
- 跑直流工作点（OP）、瞬态（TRAN）和 AC 扫描，读懂日志、游标与测量值；
- 保存 workbook、导出 CSV/PNG，留下别人能复现的记录；
- 判断哪些问题本板能仿、哪些必须查数据手册或实测，不把仿真当签字。

**难度定位：**进阶篇开始。本章不要求你会写 SPICE 网表，但要求你会判断结果是否可信。

---

## 13.1 先问一个能被判定的问题

“帮我仿真一下这个电路”不是问题。可执行的问题至少要包含四件事：

| 要素 | 反例 | 正例 |
| --- | --- | --- |
| 问题 | 电路能不能工作？ | 3.3 V 经 330 Ω 驱动 Vf≈2.0 V 的 LED 时，电流是否落在 3–5 mA？ |
| 判据 | 波形看起来对 | 工作点电流在 3–5 mA，且与手算同量级 |
| 模型 | 随便找个二极管 | 厂商 LED 模型，或明确标注为教学拟合的模型 |
| 分析 | 跑一下 | OP；若看 PWM 平均电流则用 TRAN |

KiCad 内置 ngspice 仿真器，入口在原理图编辑器的 `Inspect → Simulator`。仿真读的是同一张原理图的网表，不读 PCB 的铜皮与走线；所以它回答的是“电路拓扑与器件模型是否成立”，不是“这块板一定通过 EMC”。

```ill
kicad-ch13-sim
```

图 13-1 从原理图到仿真结果。仿真不是独立软件，它读的是同一张原理图。

### 仿真页与正式原理图分开

给仿真加的电压源、探针和测试负载，不应该悄悄进入正式 PCB 网表。两种做法：

1. 在工程里复制一份原理图页，只保留要验证的子电路，专门用于仿真；
2. 如果必须共用同一页，把只供仿真的器件在 `Symbol Properties` 里勾选 `Exclude from board`，并确认 ERC/网表没有把测试源带进 PCB。

无论哪种做法，仿真页都要能独立打开、独立运行。仿真通过后，不要把“测试源”当成真实电源写进 BOM。

> **提示：**`Simulation_SPICE` 是 KiCad 自带的仿真符号库，里面有电压源、电流源、开关、通用二极管/三极管等。仿真页的参考地要用库里的 `0` 符号，或与原理图共用的 `GND`；ngspice 需要一个明确的节点 0 作为参考。

## 13.2 模型：先确认“它代表谁”

### 可以推断的模型

电阻、电感、电容可以推断模型：KiCad 检测到符号恰好有两个引脚，且参考号以 `R`、`L`、`C` 开头时，会自动套用理想模型，只需要填 `Value`。推断出来的是理想模型：

- 理想电阻没有寄生电感/电容；
- 理想电容没有 ESR/ESL；
- 理想电感没有绕组电阻和寄生电容。

需要非理想行为时，必须显式指定模型，不能指望“推断”自动加上寄生参数。

### 手动分配模型

在 `Symbol Properties` 里点 `Simulation Model…`，打开 `Simulation Model Editor`。常用来源：

- **内置模型**：二极管、三极管、MOSFET、电压/电流源、传输线、开关等，参数在编辑器里填；
- **外部模型文件**：厂商提供的 `.model` / `.subckt`，文件必须是未加密的纯文本；
- **IBIS 模型**：数字输入/输出缓冲器可用 `.ibs`，按 `Component`、`Pin`、`Model` 选择。

外部模型的路径可以写绝对路径，也可以相对工程目录，或相对 `SPICE_LIB_DIR`。勾选 `Embed File` 会把模型文件嵌入原理图或符号库，换机器时更不容易丢；代价是原理图文件变大。

> **警惕：**一个符号只能挂一个模型，多单元符号要把模型挂在第一个单元上。模型引脚与符号引脚对不上时，仿真可能“有波形但接错了”，也可能直接不收敛。`Simulation Model Editor` 的 `Pin Assignments` 页就是用来逐脚映射的；模型里没有的引脚（例如运放的调零脚）可以映射到 `Not Connected`，同一个 `Not Connected` 可以分配给多个符号引脚。

### 最常见的引脚陷阱：二极管方向

SPICE 二极管模型通常把 pin 1 当阳极，而 KiCad 的二极管符号常把 pin 1 画在阴极。直接套模型，LED 可能反接，工作点电流接近零或大得离谱。分配完模型后：

1. 打开 `Pin Assignments`，逐个核对阳极/阴极；
2. 用 `Simulation → Show SPICE netlist…` 看生成的网表，确认二极管行的节点顺序；
3. 先跑一个简单的工作点，确认电流方向与量级，再把模型用到完整电路。

模型不是数据手册的替代品。理想运放模型不会告诉你真实运放的失调、噪声和压摆率；简化的 MOSFET 模型可能完全忽略寄生电容。模型适用范围要写进仿真记录，不能只写“用了厂商模型”。

### 教学用的 LED 模型

`Device:LED` 符号本身不会自动变成“Vf=2.0 V 的 LED”。如果手头没有厂商模型，可以用一个明确标注为教学拟合的模型练流程：

```text
.model LED_TEACH D(Is=1e-20 N=1.8 Rs=10)
```

它只是让 Vf 落在 2 V 附近，用来演示“模型参数会改变结论”，不是任何真实型号的 datasheet 模型。正式设计请换厂商模型，并把型号、版本和来源写进记录。

## 13.3 例一：LED 工作点（OP）

本板的 LED 支路是：`PB3 → 330 Ω → LED → GND`；GPIO 输出高电平时 PB3 近似 3.3 V。先手算，再仿真，最后比较。

### 手算

取 `VCC = 3.3 V`、`Vf = 2.0 V`、`R = 330 Ω`：

```text
If = (VCC - Vf) / R
   = (3.3 - 2.0) / 330
   ≈ 3.9 mA
```

若把电阻换成 1 kΩ，按同样的恒定 Vf 估算：

```text
If = (3.3 - 2.0) / 1000 = 1.3 mA
```

这两个数都是“恒定 Vf”近似。真实 LED 的 Vf 会随电流变化，仿真模型如果包含串阻和指数特性，结果会在同一量级内偏离。

### 在 KiCad 里跑 OP

1. 在仿真页放一个 `VDC` 源，正端接 PB3 所在的 `LED` 网络，负端接 `0`/`GND`，值设为 `3.3`，用来模拟 GPIO 输出高电平。本板的 LED 支路挂在 PB3，不是直接挂在 `+3V3` 上；把源并在 `+3V3` 上验证的是电源轨，不是 GPIO 驱动支路。电源符号本身不是源，没有这个 `VDC`，工作点会得到全零或奇异矩阵。
2. 放 LED、330 Ω 电阻，按本板连接好；给 LED 分配模型，核对引脚。
3. 打开 `Inspect → Simulator`，用 `Simulation → New Analysis Tab…`（`Ctrl+N`）新建 `OP` 分析，运行 `Simulation → Run Simulation`（`R`）。
4. OP 不产生曲线，结果打印在窗口下方的 output log；也可以打开 `View → Show OP Voltages` 和 `Show OP Currents`，把节点电压、器件引脚电流标注回原理图。

判据不是“有数字”，而是：

- LED 电流在 3–5 mA；
- 电流方向从阳极流向阴极；
- 与手算的 3.9 mA 同量级；
- 模型来源和 Vf 假设能解释差异。

> **警惕：**如果用一个默认的通用二极管模型，Vf 可能只有 0.6–0.7 V，OP 会算出 7–8 mA 一类的结果。这时不要改电阻去“凑”3.9 mA；先确认模型是不是 LED。模型错了，改电阻只是把错误固化进 BOM。

## 13.4 例二：RC 阶跃（TRAN）

这一节是**方法练习**，不是本板的 BOM：`usb_breath_led` 没有这个 RC，做完练习不要把它加进板子。选它是因为 RC 的解析解清楚，适合检查仿真设置有没有错。

一阶 RC 低通：

```text
Vin ── R ── Vout
             │
             C
             │
            GND
```

取 `R = 10 kΩ`、`C = 100 nF`：

```text
τ = R × C = 10^4 × 10^-7 = 1 ms
fc = 1 / (2πRC) ≈ 159 Hz
```

给 `Vin` 一个 0 → 3.3 V 的阶跃，理论上：

- `t = τ` 时，输出达到终值的 63.2%，约 `2.08 V`；
- `t = 3τ` 时，达到 95.0%，约 `3.14 V`；
- `t = 5τ` 时，达到 99.3%，约 `3.28 V`。

在 KiCad 里：

1. 放 `R`、`C`、`0`/`GND`，以及一个 `VPULSE` 源；设初始值 0、脉冲值 3.3 V、上升沿尽量短（例如 1 µs）、脉宽足够长（例如 10 ms）。
2. 新建 `TRAN` 分析：时间步长 `10u`、终止时间 `10m`、最大步长 `10u`。最大步长不设，仿真器可能跨过关键拐点，曲线看着平滑，读数却不准。
3. 运行后勾选 `Vout`，或使用 `Simulation → Probe Schematic…`（`Shift+P`）在原理图上点线取电压。
4. 打开两个游标，分别放在 1 ms 和 5 ms；游标差值会直接显示在右侧的 cursor 表格里。

```ill
kicad-ch13-wave
```

图 13-2 一阶 RC 的阶跃响应。时间常数 τ = RC 决定“多快稳定”，不是“最终到多少”。

> **提示：**在 Signals 面板里右键某个信号，选最小值、最大值、RMS、峰峰值等测量；测量对**整段仿真数据**计算，不受当前缩放影响。想量某个时间点，用游标；想量整段，用 measurement。

## 13.5 例三：AC 扫描与 LDO 稳定性

### RC 的幅频特性

把上面的 RC 换成 AC 分析：

1. 给源设置 AC 幅值（例如 `AC 1`）；
2. 新建 `AC` 分析，扫描范围 `10` 到 `100k` Hz，每十倍频程 `100` 点；
3. 勾选 `Vout`，得到 Bode 图。

在 `fc ≈ 159 Hz` 处，幅值应降到输入的 0.707（约 `-3 dB`），相位约为 `-45°`。如果曲线是平的，先检查源有没有 AC 幅值，而不是怀疑电容。

### LDO 稳定性：没有模型就不要“仿”

LDO 的环路稳定性取决于内部补偿、输出电容的 ESR、负载电流和 PCB 寄生。正确的做法是：

- 用厂商提供的平均模型（如果有），按数据手册的测试条件接好输入/输出电容与负载；
- 在反馈环路里按模型/数据手册的测试电路注入小信号，跑 AC 分析看环路增益与相位裕度，或跑 PZ 分析看极点/零点；
- 改变输出电容与 ESR，观察相位裕度是否仍在稳定区；
- 把“模型是否包含封装/PCB 寄生”写进结论。

没有厂商模型时，不要用理想运放加理想晶体管“搭一个 LDO”来证明稳定。那种模型通常过于乐观，结论没有证据价值。此时应：

1. 查数据手册的“稳定 ESR 范围”和负载条件；
2. 在首件上实测输出纹波、负载跳变响应；
3. 在记录里明确写“无厂商模型，未做环路仿真”。

> **版本差异：**`PZ`（极点-零点）分析存在，但它和 `OP` 一样不产生曲线，结果打印在 output log。不要因为“图是空的”就判定分析失败。

## 13.6 仿真与 PCB 的差距：信号完整性不是电路仿真的自动产物

ngspice 是**电路级**仿真器，它读原理图网表，不会自动提取 PCB 的走线电感、过孔电感、地平面阻抗和器件间的耦合。仿真通常假设：

- 理想电源/地；
- 零寄生走线电感/电容；
- 恒定温度；
- 器件模型在标称值。

真实 PCB 有走线电阻/电感、过孔电感、地平面阻抗、温度漂移和器件批次差异。所以：

- 仿真适合验证拓扑、工作点、趋势和参数灵敏度，不适合预测精确到 mV/ns 的波形；
- 高速/射频/电源完整性需要专门的 SI/PI 工具或实测，不能拿 ngspice 的集总参数模型代替；
- 仿真通过后，仍要做首件测试。

本板是 USB-C **仅供电**、内部 RC 时钟、低速 GPIO 的板子，没有 D+/D- 数据线，信号完整性不是本板的验收项。若以后增加 USB 数据、外部晶振或射频模块，再按第 7 章的差分/参考面要求处理，并用叠层与实测确认阻抗；那时才需要 SI 工具，而不是在本章硬加一个“看起来像高速”的仿真。

## 13.7 把结果变成可复核的证据

仿真最容易犯的错不是算错，而是“只有一张截图，别人复现不了”。建议每次仿真留下五项：

```text
问题/判据：
模型与来源（型号、版本、文件）：
分析类型与参数（OP/TRAN/AC，起止范围、步长）：
结果（数值/曲线/日志）：
结论与未覆盖因素：
```

具体做法：

- **Workbook**：`File → Save Workbook` 保存分析设置、已绘信号、用户定义信号、测量、游标和显示设置；`File → Open Workbook` 恢复。workbook **不保存仿真结果**，重开后要按原参数再跑一次。
- **CSV**：`File → Export Current Plot as CSV…` 导出当前绘图的数据。只有勾选了 `Plot` 复选框的变量会进入 CSV；文件用**分号**分隔，不是逗号。OP/PZ 没有绘图，不能这样导出，抄 output log 或使用 OP 标注。
- **PNG**：`File → Export Current Plot as PNG…` 保存当前可见绘图，适合放进评审记录；它不能替代 CSV，因为像素不能重新计算。
- **模型与工程一起提交**：外部 `.lib`/`.sub` 文件、workbook、CSV 和一段文字结论放进版本控制；模型有许可限制时，至少记录型号、来源和校验值，不要只留一个本地路径。

> **提示：**调参时可以用 `Simulation → Add Tuned Value…`（`Shift+T`）把电阻/电容/直流源加进调节面板，单次运行或 `Multi Run` 扫描多个值，并限制到 E24/E48/E96/E192 系列。`OP` 分析不能调参；调参只适用于会产生绘图的仿真。

## 13.8 常见故障与排查

| 现象 | 可能原因 | 先查什么 |
| --- | --- | --- |
| 运行后没有曲线 | 没有选中信号；`Save all voltages` 未开；当前不是活动分析页 | 在 Signals 面板勾选节点，或按 `P` 探针；确认活动标签页 |
| OP 的电流大得离谱 | 二极管方向/引脚映射错；用了通用二极管当 LED；源电压接错 | `Pin Assignments`、`Show SPICE netlist…`、模型 Vf |
| 报 “timestep too small” | 模型不收敛；引脚映射错；缺电源或地；电路拓扑本身矛盾 | 先补全电源/地，核对模型引脚；最后才考虑收敛选项 |
| AC 曲线是平的 | 源没有 AC 幅值；探针选错节点 | 源参数里加 AC 幅值；重新探针 |
| 结果与手算差一个数量级 | 单位前缀写错（`m` 是毫，`M` 是兆）；模型参数错；电阻值单位错 | 逐一核对 `Value`、模型参数和前缀大小写 |
| `.plot` 指令没有效果 | KiCad 不支持 ngspice 的 `.plot` | 改用 Signals 面板勾选或探针 |

收敛选项是最后手段，不是第一步。手册给出的常用指令包括：

```text
.options gmin=1e-10
.options abstol=1e-10
.options reltol=0.003
.options cshunt=1e-15
```

这些值会改变求解精度，可能把“算不出来”变成“算出一个错的结果”。只有在确认拓扑、电源、地和引脚映射都没问题后，才逐条尝试，并在记录里写明改了哪一项、为什么改。

## 13.9 本板能仿什么，不能仿什么

| 问题 | 手段 | 本板结论 |
| --- | --- | --- |
| LED 电流是否在 3–5 mA | OP + 手算 | 可验证，前提是 LED 模型与实物一致 |
| 复位上拉、按键静态电平 | OP | 可验证静态电平；按键抖动不覆盖 |
| LDO 的 3.3 V 输出与稳定性 | 厂商模型 + AC/PZ，或实测 | 没有厂商模型时只能记录“无法验证” |
| USB-C 的 CC1/CC2 5.1 kΩ 下拉 | 静态计算/ERC | 不需要 ngspice |
| 回流路径与 EMC | 第 8 章人工检查 + 实测 | 电路仿真不覆盖 |
| 信号完整性 | SI 工具/实测 | 本板无数据线，不适用 |

这张表比“仿真通过”四个字有用：它告诉评审人，哪些结论有证据，哪些还是空白。

## 本章小结

- 仿真要先有问题、判据、模型和分析；没有判据的曲线只是图片。
- 电阻/电感/电容可推断理想模型；LED、运放、LDO 等必须显式分配模型并核对引脚。
- OP 看静态工作点，结果在日志/标注里；TRAN 看时域；AC 看频域；PZ 也输出到日志，不画曲线。
- 模型决定结论：用通用二极管代替 LED，会把电流算错；没有厂商 LDO 模型，就不要声称验证了稳定性。
- workbook 保存设置不保存结果；CSV 用分号分隔，且只导出勾选 `Plot` 的变量；OP/PZ 不能导出绘图。
- ngspice 是电路级仿真，不替代 PCB 寄生提取、SI/PI 工具和首件实测。

## 练习

1. 按 13.3 跑 LED 的 OP：先用教学模型，再换一个默认二极管模型，记录两次电流差异，并解释哪一次不能作为设计依据。
2. 按 13.4 跑 RC 的 TRAN，用游标读出 1 ms 与 5 ms 的电压，与 63.2%/99.3% 的解析值比较；把最大步长改成 `1m` 再跑一次，观察误差。
3. 给 RC 跑 AC 扫描，确认 `-3 dB` 点在 159 Hz 附近；导出 CSV，检查分隔符和列名。
4. 找一个有 SPICE 模型的 LDO，按数据手册条件跑 AC；如果没有模型，写下“无法验证”的理由和下一步实测项。

## 验收

- 仿真页与正式原理图分离，测试源没有进入 PCB 网表；
- 每个器件的模型来源、引脚映射和适用范围都有记录；
- OP/TRAN/AC 的结果与手算或数据手册在同一量级，差异能解释；
- 能说出仿真没有覆盖哪些真实因素，以及本板哪些问题必须实测；
- 别人拿到 workbook、模型和 CSV 能复现同一结果。

下一章回到“库”：自定义符号、封装、3D 模型与团队规范。仿真和制造都依赖库的准确性，库错了，后面全错。
