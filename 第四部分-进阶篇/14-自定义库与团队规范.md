# 第 14 章：自定义库与团队规范——符号、封装、3D 与 KLC

> **开门一句话：**库由团队共用；库里的错误可能在新建或更新器件时传播到多个工程，因此发布后要通知使用方。

## 学习目标

读完这章，你能做到：

- 在符号编辑器里创建/修改符号，设置引脚类型、编号、单位与替代外形；
- 在封装编辑器里创建焊盘、丝印和 courtyard；知道 3D 模型是可选的可视化/结构检查资料；
- 按 KLC 的基本规则命名和布局，减少团队评审成本；
- 用 Git 管理库，处理“库改了，旧工程怎么办”。
- 用 `${KIPRJMOD}` 建立可移植的工程库表，能在换目录/换机器后定位并恢复丢失的库或库表；

**难度定位：**进阶篇。本章偏规范，但每个规范都对应一个真实故障模式。

---

## 14.1 符号编辑器：从“能画”到“能被检查”

创建符号的步骤：

1. `File → New Symbol`，命名（例如 `ATtiny85-20SU`）；
2. 放矩形/线条，画本体；
3. 放引脚，设置编号、名称、电气类型；
4. 设置参考号/值的位置；
5. 填写 `Footprint`、`Datasheet`、`Description` 等字段；
6. 保存到项目库或官方库（项目库优先）。

### 引脚编号与名称

- **编号**：必须与封装焊盘一致；
- **名称**：功能名（`VCC`、`PB0`、`RESET`）；
- **电气类型**：KiCad 10 共 12 种——`Input`、`Output`、`Bidirectional`、`Tri-state`、`Passive`、`Free`、`Unspecified`、`Power input`、`Power output`、`Open collector`、`Open emitter`、`Unconnected`。旧资料常只列 8 种，漏掉 `Free`、`Open emitter`、`Unconnected`；建库时别照抄旧清单，类型选错会直接改变 ERC 的结论。
- **隐藏引脚**：电源引脚可以隐藏，但会增加“看不见的连接”，新手容易出错；建议不隐藏，或明确标注。

### 多单元与替代外形

一个器件可以有多组单元（例如双运放的两个通道），也可以有替代外形（De Morgan 等）。KiCad 10 支持多个替代 body style；旧版本只有一组 De Morgan 替代。创建时想清楚：

- 单元如何分配引脚；
- 替代外形是否改变引脚位置；
- 封装是否共用。

### 引脚表 CSV

KiCad 10 的符号编辑器提供 **Pin Table**（引脚表）按钮，能以表格形式一次看到并批量修改全部引脚，比逐个点开引脚属性更适合 MCU、连接器这类多引脚器件。它还能与外部表格工具互传：

- 导出：**To File…** 或 **To Clipboard**，格式为逗号分隔（CSV）；所有引脚属性列都会导出，包括表格中隐藏的列；**Count** 汇总列不导出。
- 导入：**From File…** 或 **From Clipboard**，接受 CSV 或 TSV；**必须有表头行**，列按**列名**匹配。对不上的列被忽略，缺失的列用默认值填充；可选“替换全部引脚”或“追加”。

```csv
Number,Name,Type,Style
1,VCC,power_in,line
2,PB3,bidirectional,line
...
```

> **提示：**上面只是示意表头，不是 KiCad 规定的列名。动手前先用引脚表的 **To File…** 导出一个真实符号，照它给出的列名改，再 **From File…** 导回；列名对不上时 KiCad 会弹出错误提示框并列出未知列；确认后忽略这些列继续导入，取消则放弃导入。引脚编号/名称/类型一旦发布就不要随意改；改了要通知所有使用该库的工程。

## 14.2 封装编辑器：焊盘、丝印、courtyard

KiCad 的可制造封装基线关注焊盘、丝印和 courtyard；3D 模型是附加资料，不是完成 ERC、DRC 或导出制造文件的前提：

- **焊盘**：数量、编号、尺寸、间距、形状（矩形/圆形/圆角/异形）；
- **丝印**：本体外框、pin 1 标记、极性标记；
- **courtyard**：器件占位边界，用于 DRC 防重叠；
- **fab 层**：装配图轮廓、参考号。

有准确的器件模型时，可给封装关联 STEP 或 VRML，供 3D 视图与结构检查使用；缺模型不代表封装不能制造。若依赖 3D 视图判断器件高度或器件间干涉，模型尺寸和原点必须另按器件资料核对；外壳配合则要把板子与外壳 STEP 导入机械 CAD，或按外壳图纸核对。


图 14-1 符号与封装定义电气和焊接关系；3D 模型是可选的结构检查补充，不是每个封装的必备文件。

### 焊盘尺寸从哪来

以 SOIC-8 为例：

- 引脚间距 `e = 1.27 mm`；
- 引脚宽度 `b = 0.4–0.5 mm`；
- 引脚长度 `L = 1.0–1.5 mm`；
- 焊盘宽度 = `b + 0.2–0.4 mm`（取决于工艺）；
- 焊盘长度 = `L + 0.3–0.6 mm`（形成脚跟/脚尖 fillet）。

具体按 IPC-7351 或数据手册的 recommended land pattern。不要凭“看起来差不多”画。

### courtyard

courtyard 是器件+焊点+返修空间的外边界。规则：

- 在本体和焊盘外留出装配间隙；KLC 默认留边 0.25 mm，小器件及部分封装类别另有规定（见 14.3）；
- 两个器件的 courtyard 不能重叠；
- 连接器要考虑插拔空间；
- 测试点/探针空间也要算进去。

DRC 的 `Courtyards overlap` 检查的就是这个边界。

### 3D 模型

新封装优先挂 STEP 模型；KiCad 官方库为每个模型同时提供 STEP 与 VRML，旧库可能只有 VRML。3D 模型要：

- 尺寸/原点与封装一致；
- 不要包含无关的夹具/包装；
- 文件名与封装对应；
- 复杂模型可以简化，但关键外形（连接器、散热器）要准确。

> **版本差异（易错）：**KiCad 的官方封装库为**每个**模型同时提供 STEP 与 VRML（`.wrl`），但库里的封装默认只引用 VRML。VRML 不会进入 STEP/BREP/XAO 导出；导出 STEP 时必须勾选“替换同名模型”（CLI 为 `--subst-models`），导出器才会改用对应的同名 STEP/IGS。**没有可替换的 STEP/IGS 时，该器件模型会缺失，不会回退到 WRL。** 因此导出 STEP 后要检查器件模型是否齐全；做机械 CAD 装配校核时优先 STEP。
> **可选与必需：**3D 模型不是 ERC/DRC 或制造输出的必需项，缺模型只影响 3D 视图与结构校核。读者做本书的基础工程时可以先不逐个配模型，需要结构检查时再补。

## 14.3 KLC：可检查的约定

KLC（KiCad Library Convention）是 KiCad 官方符号/封装库贡献指南。KLC 明确称其为 guidelines，而非没有例外的 rules；库团队可酌情允许例外，若与器件数据手册或制造商建议冲突，原则上优先采用数据手册，除非有经说明的理由（KLC 总则）。它适合作为团队库的兼容性基线，具体条目仍要按元件类型和数据手册核对。

几条常用的符号与封装约定：

- 符号主体轮廓线宽为 10 mil（0.254 mm，S3.3）；
- 引脚原点落在 100 mil（2.54 mm）栅格节点上；这条要求针对引脚原点，不代表符号里的所有图元都必须使用 100 mil 栅格（S4.1）；
- 引脚长度至少 100 mil，按 50 mil 递增；参考引脚编号字符数确定长度，最大 300 mil。简单分立器件可用更短引脚，同一符号的引脚长度应一致（S4.1）；
- `Reference` 与 `Value` 字段应按符号类型正确设置并保持可见。S6.2 未规定它们必须分别位于符号上方和下方；团队可另订字段排布约定；
- 封装命名按对应类别的 KLC 命名条目执行。焊盘与封装尺寸应优先核对数据手册和制造商建议；KLC 总则也明确数据手册的优先级；
- courtyard 默认留边为 0.25 mm；任一器件尺寸小于 1.5 mm 时可用 0.15 mm，连接器、罐形电容、晶体和 BGA 等另有规定（F5.3）；
- 丝印应避开焊盘和裸露铜，并提供可见的极性或 pin 1 标记（F5.1）。

完整条目见 [KiCad Library Convention（本轮核对提交 6e8cbad9）](https://gitlab.com/kicad/libraries/klc/-/tree/6e8cbad9556359879d2b91f904d6df82517d97d1)。团队可按项目需要增加规则，并将偏离 KLC 的理由记录下来。

## 14.4 库的版本管理

库和工程一样，应该进 Git。推荐结构：

```ill
kicad-ch14-git
```

图 14-2 库的版本历史：每次评审打标签，出问题能回到任意一个可用版本。

```text
lib/
├── symbols/
│   └── team.kicad_sym
├── footprints/
│   └── team.pretty/
│       ├── SOIC-8_3.9x4.9mm_P1.27mm.kicad_mod
│       └── ...
└── 3d/
    └── SOIC-8.step
```

**库表放在哪里、路径怎么写**（KiCad 10）：

- 符号库表与封装库表各有两份：**全局表**在 KiCad 用户配置目录，对所有工程生效；**工程表**只在当前工程目录下存在时生效，二者都叫 `sym-lib-table` / `fp-lib-table`。管理入口是 **Preferences → Manage Symbol Libraries… / Manage Footprint Libraries…**。
- 团队库优先登记在**工程表**：在符号/封装编辑器里新建库时，文件浏览器里选择加入 **Project**（工程表），而不是 **Global**（全局表）。这样库跟着工程走，不依赖每台机器的个人配置。
- 路径变量：`${KIPRJMOD}` 展开为**当前工程目录的绝对路径**。写 `${KIPRJMOD}/lib/symbols/team.kicad_sym` 这样的 URI，工程整体搬到别处后无需手改；写死 `D:/...` 则一定在新机器上断掉。封装库是 `.pretty` 目录，同样用 `${KIPRJMOD}/lib/footprints/team.pretty`。
- 官方库用版本化变量 `${KICAD10_SYMBOL_DIR}`、`${KICAD10_FOOTPRINT_DIR}`；3D 模型路径也可用变量（**Preferences → Configure Paths…**）。旧变量如 `${KICAD9_SYMBOL_DIR}` 会自动解析到当前版本对应变量，前提是本机的确没有显式定义旧变量。

**必须进 Git（读者必做）**：`.kicad_pro`、`.kicad_sch`、`.kicad_pcb`、两个库表、库文件（`*.kicad_sym`、`.pretty/`），以及需要的 3D 模型或其下载脚本。

**不要进 Git（自动生成或本机私有）**：`.kicad_prl`（本机界面状态）、`fp-info-cache`、`<工程名>-backups/`（自动备份目录）。库的变更说明（新增/修改/弃用）写进提交信息或 `lib/CHANGELOG.md`。

### 库改了，旧工程怎么办

- **不要直接改已发布的库**：旧工程可能依赖旧焊盘；
- 新增版本（`team_v2.kicad_sym`）或新封装名；
- 在库的 `Description` 里写“since 2026-11”；
- 旧工程需要时，显式迁移并重新跑 DRC。

> **警惕：**库是“共享依赖”，修改的影响范围比单个工程大。一次“顺手改一下焊盘”，可能让十个已投产的工程变成不可复现。改库要像改公共 API 一样谨慎。

## 14.5 团队评审：库的“代码审查”

库的评审重点：

- 引脚编号/名称/类型是否与数据手册一致；
- 焊盘尺寸/间距/ courtyard 是否按规范；
- 3D 模型是否匹配；
- 命名是否符合 KLC/团队约定；
- 是否有重复/冲突的库项；
- 是否附带数据手册链接/来源。

评审记录可以放在 Git 提交信息或 `lib/CHANGELOG.md`。不要只靠“我记得改过”。

## 14.6 从库到 BOM：字段的源头

库里的 `MPN`、`Manufacturer`、`Description` 会进入 BOM。若库字段为空，每个工程都要手填，容易错。建议：

- 常用器件在库里预填 MPN/Manufacturer；
- 项目专用器件在原理图里覆盖；
- BOM 导出前检查空字段；
- 定期清理“临时/未验证”库项。

## 14.7 可移植性实战：换目录、换机器、库丢了怎么办

本节把一个可重复的演练串起来，所有文件都在读者自己的 `usb_breath_led` 工程里生成；本书不附带任何工程文件。

### 准备：让库表跟着工程走

1. 在符号编辑器里新建工程专用符号库，保存到 `lib/symbols/usb_breath_led.kicad_sym`；在封装编辑器里新建 `lib/footprints/usb_breath_led.pretty/`。新建库时在选择库表的对话框里选 **Project**（工程表），不要选 **Global**。
2. 打开 **Preferences → Manage Symbol Libraries…** 与 **Preferences → Manage Footprint Libraries…**，切到 **Project Specific** 标签，确认两条 URI 分别是 `${KIPRJMOD}/lib/symbols/usb_breath_led.kicad_sym` 和 `${KIPRJMOD}/lib/footprints/usb_breath_led.pretty`，不是盘符开头的绝对路径。
3. 提交这六样：`.kicad_pro`、`.kicad_sch`、`.kicad_pcb`、`sym-lib-table`、`fp-lib-table`、`lib/`。

### 制造故障：在干净目录里故意漏掉库

1. 建立**一次性验证副本**，只在副本里移走两个库表和 `lib/`；不要在唯一工作副本里临时改名或移动原文件。
2. 用 KiCad 10 打开 `.kicad_pro`，逐项观察并记录：

| 观察点 | 预期现象 | 原因 |
| --- | --- | --- |
| 原理图 / PCB 画面 | 符号与封装通常仍显示 | `.kicad_sch` 内嵌 `lib_symbols` 缓存，`.kicad_pcb` 内嵌封装几何；有些构建还会在打开时弹库缺失提示，记下原文 |
| Preferences → Manage … Libraries → Project Specific | 工程库条目消失，或 URI 显示为找不到/无效 | 库表文件缺失，或其指向的目录不存在 |
| Tools → Update Symbols from Library… / Tools → Update Footprints from Library… | 报“库/符号/封装未找到”，更新失败 | 更新操作必须读回库文件，缓存顶不上 |

3. 写下窗口名、URI 和提示措辞，作为验收证据；只“看一眼觉得不对”不算完成。

### 恢复：把路径变量指回工程目录

1. 在一次性验证副本中把 `lib/` 和两个库表放回。若它们已提交且副本工作区干净，可在**该副本**运行 `git restore --worktree -- sym-lib-table fp-lib-table lib/`；不要在含有未提交修改的原工程运行恢复命令。
2. 再进 **Preferences → Manage … Libraries → Project Specific**，若条目被改成了绝对路径，改回 `${KIPRJMOD}/lib/...` 后保存。
3. 重跑 **Tools → Update Symbols from Library…** 与 **Tools → Update Footprints from Library…**，确认不再报缺失；在 3D 查看器确认能显示的模型恢复显示。
4. 再跑一次 ERC/DRC，确认没有因库缺失新增违规；单独提交一条“修复库表路径”的变更，不要和电路改动混在一起。

**判定通过**：工程整体换到任意目录/机器后，只要 `lib/` 相对工程的位置不变，`${KIPRJMOD}` 会自动指向新位置，库表无需手改；移走库表或 `lib/` 时能稳定复现“找不到库”，放回后能稳定消除。

## 本章小结

- 符号的关键是引脚编号/名称/类型；封装的关键是焊盘/丝印/courtyard，3D 模型按需添加。
- KLC 是可检查的约定，减少团队评审成本。
- 库要进 Git，用相对路径，改库要像改公共 API 一样谨慎。
- 工程库表用 `${KIPRJMOD}` 才能换目录/换机器不失效；移走库表或库要能复现故障并恢复。
- 库字段是 BOM 的源头，空字段会在采购/贴片时变成问题。
- 库评审要记录，不靠记忆。

## 练习

1. 按数据手册创建一个 SOIC-8 封装，先完成焊盘、丝印与 courtyard；**选做：**若能取得准确模型，再关联 3D 并核对外形尺寸。
2. 给一个连接器创建符号，设置正确的引脚类型和编号，并与封装核对。
3. 完成 14.7 的“换目录/换机器”演练：按 `${KIPRJMOD}` 登记工程库，故意移走库表或 `lib/`，记录“找不到库”的现象，再恢复并确认现象消失。

## 验收

- 符号与封装的引脚对应，courtyard 不重叠、丝印不压焊盘；如提供 3D 模型，模型与器件外形相符。
- 库表使用相对路径，工程可移植；
- 能复现“移走库表/库 → 报未找到 → 放回并修正 `${KIPRJMOD}` 路径 → 恢复”的完整过程，且未把 `.kicad_prl`、`-backups/` 提交。
- 库有变更记录，旧工程可追溯；
- BOM 字段无空值（或空值有解释）。
