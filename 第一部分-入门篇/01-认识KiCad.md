# 第 1 章：认识 KiCad——从工程数据到制造输出

> **开门一句话：**KiCad 更像一条流水线：把电气意图一路翻译成制造文件。每个编辑器只是流水线上的一个工位。

## 学习目标

读完这章，你能做到：

- 说清工程文件、原理图、PCB 与符号/封装库分别负责什么，以及制造数据从哪里导出；
- 从项目管理器进入原理图、PCB、符号库和封装库，并知道它们为什么分开；
- 新建 `usb_breath_led` 工程，保存一次，并在文本编辑器里认出文件格式；
- 用 `kicad-cli version` 确认自己正在用哪个版本。

**难度定位：**起步段。本章不要求画完任何电路，重点是建立“文件—编辑器—制造输出”的地图。

---

## 1.1 从一块板倒推：它经历了什么

拿起一块常见的两层 PCB，你能看到绿色阻焊、白色丝印、银色焊盘和黑色芯片。把这些外观一层层剥掉，剩下的是几样很朴素的东西：

- 一张**原理图**：哪个引脚连到哪个网络，哪个元件用什么值；
- 一张**板图**：每个封装放在哪里，铜线怎么走，孔打在哪里；
- 两类**库定义**：符号库描述原理图符号，封装库描述焊盘图形；3D 模型是可选的外部关联文件；
- 一个**工程文件**：保存项目设置，并帮助组织这份设计；
- 按需导出的**制造数据**：例如 Gerber、钻孔文件、贴片坐标和物料清单。

这几类角色不对应工程目录中的固定文件数量。原理图和 PCB 是设计文档；库由库表定位，可能来自全局库或项目库；制造数据则按项目与工厂要求，从设计数据中导出。`.kicad_pro` 使用 JSON 格式，原理图和 PCB 使用 s-expression 格式，不能把整个工程笼统说成一组文本文件。理解这些关系后，你可以判断哪些源文件要与工程一起版本控制，哪些输出需要交给工厂。

```ill
kicad-ch01-flow
```

图 1-1 工程与设计数据的关系：原理图同步至 PCB；制造数据由 PCB 导出，BOM 则从原理图生成；符号库与封装库为两者提供对象定义。

## 1.2 工程、原理图、PCB 与两类库

### 工程文件 `.kicad_pro`

工程文件是“总目录”。它不保存电路本身，而是保存这个工程的设置：网类、ERC/DRC 严重程度、输出路径、仿真选项、图纸模板与文本变量等。双击它，KiCad 项目管理器会打开整个工程。

工程文件是 JSON 格式，可以用文本编辑器打开。里面有 `board`、`schematic`、`libraries`、`text_variables` 等配置键。通常不需要手改它；换电脑或重建工程环境时，应把它和原理图、PCB 以及需要的工程级配置一同归档。工程文件本身不包含这些设计文档。

### 原理图 `.kicad_sch`

原理图文件保存符号、导线、网络标签、电源符号、图纸层次和注释。它是 s-expression 文本，下面以一份保存结果示意文件头；格式版本可能随文件格式升级变化，实际值以本机文件为准：

```text
(kicad_sch (version 20260306) (generator "eeschema") (generator_version "10.0")
  (uuid ...)
  (paper "A4")
  ...
)
```

原理图回答的是“电气上谁连着谁”。它不关心封装多大、板子多长，也不关心铜线怎么绕。把这些事分开，是为了让同一个电路可以换封装、换板形，而不必重画电气连接。

### PCB 文件 `.kicad_pcb`

PCB 文件保存板框、层叠、封装实例、走线、过孔、铺铜、丝印、DRC 标记等。它也是 s-expression 文本。下面以一份保存结果示意文件头；格式版本可能随文件格式升级变化，实际值以本机文件为准：

```text
(kicad_pcb (version 20260206) (generator "pcbnew") (generator_version "10.0")
  (general (thickness 1.6))
  (layers ...)
  (setup ...)
  (net 0 "")
  ...
)
```

原理图与 PCB 之间靠**网络表**和**封装引用**对应，不能直接复制粘贴：原理图里的每个符号实例有一个 footprint 字段，PCB 里的每个封装有对应的 reference 和 pad。KiCad 在后台维护这份对应关系，所以你可以从原理图“更新 PCB”，也可以从 PCB 反标注。

### 符号库 `.kicad_sym`

符号库定义“这个器件在原理图上长什么样”：几根引脚、引脚叫什么、电气类型是什么、参考号和值放在哪里。它不包含焊盘尺寸，也不包含 3D 形状。

### 封装库 `.kicad_mod`

封装库通常是 `.pretty` 目录，里面按封装分别保存 `.kicad_mod` 文件。封装定义器件在 PCB 上的焊盘、间距、尺寸、阻焊开窗、丝印外框和 courtyard；它不关心引脚在原理图里叫什么，只关心焊盘编号。3D 模型可以作为另一个路径引用，不是每个封装都有。

> **提示：**把符号和封装想成“同一枚硬币的两面”。符号上的 pin number 与封装上的 pad number 必须一一对应；对不上，电气连接就会落到错误的焊盘上。

```ill
kicad-ch01-toolmap
```

图 1-2 项目管理器与各个编辑器。它们共享同一套工程与库，但各自只负责一类对象。

## 1.3 还有哪些文件值得认识

除了五个主角，工程目录里常见这些文件：

| 文件 | 作用 | 是否要进版本库 |
| --- | --- | --- |
| `sym-lib-table` | 本工程使用的符号库列表 | 要 |
| `fp-lib-table` | 本工程使用的封装库列表 | 要 |
| `.kicad_prl` | 本地界面状态（窗口位置、最近层） | 一般不要 |
| `.kicad_dru` | 自定义 DRC 规则 | 要 |
| `.kicad_wks` | 图纸模板（标题栏、边框） | 要，若团队统一 |
| `.kicad_jobset` | 一键输出作业集 | 要 |
| `<工程名>-backups/` | KiCad 自动备份目录 | 不要 |
| `fp-info-cache` | 封装库缓存，可重建 | 一般不要 |

这张表背后有一条简单原则：**能描述设计意图的文件要进版本库，能由工具重建的缓存不进**。`fp-info-cache`、`.kicad_prl`、备份文件都属于后者。

## 1.4 安装与版本：先固定，再开始

KiCad 官方提供 Windows、macOS 和 Linux 安装包。写作时最新稳定系列是 10.0.x；官网下载页会同时提供稳定版和夜间构建版。教学和团队协作应使用稳定版，并把版本号写进 README。

安装完成后，先在终端确认命令行工具可用：

```bash
kicad-cli version
```
命令成功时会输出 KiCad 版本号；确认它属于本书的 `10.0.x` 主线，并把实际补丁号记入工程 `README.md`。若终端找不到命令，按下面的系统路径重试。

在 Windows 上，如果提示找不到命令，通常是安装目录没有进 `PATH`。默认路径类似：

```text
C:\Program Files\KiCad\10.0\bin\kicad-cli.exe
```

可以直接用完整路径调用，或把 `bin` 目录加入用户环境变量。macOS 的 `kicad-cli` 在：

```text
/Applications/KiCad/KiCad.app/Contents/MacOS/kicad-cli
```

> **版本差异：**KiCad 的主版本会改变文件格式。新版本能打开旧文件，但旧版本打不开已经被新主版本保存过的文件。升级前先备份，团队内先统一主版本。

## 1.5 新建工程：从空目录开始

打开 KiCad 项目管理器，选择 `File → New Project`，把工程命名为 `usb_breath_led`，放在一个空目录里。建议目录名只用小写字母、数字和下划线，避免空格与中文路径：KiCad 本身支持，但脚本、CI 和工厂上传工具经常在这里出问题。

新建完成后，项目管理器里会出现三个空文件：

- `usb_breath_led.kicad_pro`
- `usb_breath_led.kicad_sch`
- `usb_breath_led.kicad_pcb`

KiCad 10 在 `File → New Project` 时一次创建这三个文件；`.kicad_pcb` 不必等到“更新 PCB”才出现。后面打开 PCB 编辑器或执行正向标注时，编辑的就是这个已经存在的空板文件。

> **前提与预期观察：**首次启动 KiCad 时通常会弹出“复制默认全局库表”的对话框；若跳过，稍后按 `A` 搜索符号会找不到器件。新建工程前先确认全局符号/封装库表已配置好；新建成功后，目录里应同时看到上述三个文件。

> **失败路径：**如果目录里只有 `.kicad_pro`，而没有 `.kicad_sch`/`.kicad_pcb`，多半是用了“另存为单文件”而不是 `File → New Project`。回到项目管理器用 `File → New Project` 重建；不要手工建空文件冒充工程。

在原理图编辑器里按 `Ctrl+S` 保存，然后用文本编辑器打开 `.kicad_sch`。你会看到 s-expression：括号套括号，每个对象一行。现在不需要读懂全部，只要确认三件事：

1. 文件是纯文本，不是二进制；
2. 里面有 `(symbol ...)`、`(wire ...)`、`(label ...)` 这样的结构；
3. 文件开头有版本号和生成器名。

这三件事决定了后面所有自动化与版本控制的可能性。

## 1.6 界面共同语言：工具、选择与 Esc

KiCad 的各个编辑器共享一套交互习惯：

- **工具**：工具栏上的每个按钮是一种“模式”。默认是选择工具；点了“放置符号”就进入放置模式。当前工具会高亮，状态栏右下角会显示工具名。
- **选择方向**：从左向右拖框，只选中完全落在框内的对象；从右向左拖框，选中碰到框的对象。这个区别在密集布局里非常有用。
- **Esc**：第一下取消当前动作（例如正在画的线），第二下退出工具回到选择模式；在选择模式下按 Esc 清空选择。
- **单位切换**：`Ctrl+U` 在毫米与 mil 之间切换（具体快捷键可能随平台变化，以 `Preferences → Hotkeys` 为准）。
- **栅格**：原理图常用 50 mil 或 1.27 mm 栅格；PCB 常用 0.25 mm 或 0.1 mm。栅格帮助引脚、导线和过孔对齐，减少端点未重合；栅格本身不保证可制造性，间距、线宽和孔径仍要按规则并用 DRC 核对。

> **警惕：**不要用鼠标“目测”把线接到引脚上。KiCad 只认端点重合；看起来碰到了但没落点，ERC 会报未连接，或者更糟——网络表里少了一条连接。

## 1.7 第一次保存与备份

在进入第 2 章之前，做三件事：

1. 在工程根目录建一个 `README.md`，写下 KiCad 版本、工程名、日期和“这是教学工程”的说明。
2. 把整个目录初始化为 Git 仓库，提交一次空工程。原理图和 PCB 都是文本，diff 可读；从第一天开始用版本控制，比最后再补容易得多。
3. 在 `fab/` 下建一个空目录，后面所有制造输出都放这里；不要把 Gerber 散落在工程根目录。

```bash
git init
git add .
git commit -m "chore: 初始化 usb_breath_led 教学工程"
```

如果暂时不想用 Git，至少复制一份带日期的备份目录。PCB 设计最常见的损失是改坏了却回不去；会不会画并不是主要风险。

## 本章小结

- KiCad 工程由工程文件、原理图、PCB、符号库、封装库五类核心文件组成，外加库表和规则文件。
- 原理图描述电气意图，PCB 描述物理实现，二者通过符号的 footprint 字段与 pad 编号对应。
- 工程设置、原理图、PCB 和库定义采用结构化文件格式，适合纳入版本控制和脚本处理；制造输出则按各自格式生成。主版本升级可能改变工程/设计文件格式，升级前要备份并统一团队版本。
- 界面共享“工具—选择—Esc”的交互模型；栅格和端点重合是连接正确的前提。
- 开始前用 `kicad-cli version` 确认 KiCad 为 `10.0.x`，并把实际补丁号记入工程 README。

## 练习

1. 新建一个空工程，保存后分别用 KiCad 和文本编辑器打开 `.kicad_pro`、`.kicad_sch`，各找出三个你认识的键。
2. 在原理图里放一个电阻符号，保存，观察 `.kicad_sch` 中新增了哪些行。
3. 运行 `kicad-cli version`，把输出贴到工程的 `README.md` 里。

## 验收

- 你能不打开 KiCad，仅凭目录里的文件说出这个工程做到哪一步；
- 你能解释“为什么原理图里改了封装，PCB 不一定会自动更新”；
- 你的工程目录里没有 `.kicad_prl`、备份文件和缓存被误提交。
- `kicad-cli version` 确认主、次版本为 `10.0`，工程 README 记录实际补丁号；命令不可用时能通过安装路径调用。
